# BangumiBar v1.2.0

## 版本简介

本版本带来了追番体验上最明显的一项改进：更新状态不再按“档期日期”粗略判断，而是使用日本放送表的真实播出时刻。同时对安全边界做了一次彻底收口——渲染层不再具备直接访问网络的能力，全部请求经主进程统一出网；顺带修掉了安装包体积与 Dock 图标两个遗留问题。

## 主要更新

### 精确播出时间

- 分集小圆点、待看徽标、下一集标签改用真实播出时刻判断，不再是“档期早于今天才算已播”
- 支持 `25:30` 这类日本深夜档的跨日表示，按 JST（UTC+9）换算到本地时区
- 到点自动更新：卡片会对准下一集的播出瞬间刷新状态，不需要手动点刷新
- 放送表暂时取不到时自动退回按日期判断，刷新按钮变橙并在悬浮提示中说明当前处于降级状态
- 修复在 UTC 负偏移时区下播出日期与星期整体差一天的问题

### 安全性收口

- 渲染层不再直接发起网络请求，全部经主进程统一出网，并受“仅 https + 主机白名单”约束
- 恢复 `webSecurity` 默认值，删除此前对**任何**站点无条件接受非法 TLS 证书的旁路
- 页面补齐 Content Security Policy，其中 `connect-src 'none'` 把“网络只走主进程”变成浏览器层面的强制约束
- OAuth 的 `client_secret` 移出前端产物，只保留在主进程
- 请求的 `User-Agent` 现在能真正生效（此前在渲染层会被浏览器静默丢弃）

### 打包与修复

- 安装包体积下降：移除了误入运行时依赖的 `esbuild`，dmg 由 100MB 降至 92MB
- 修复安装版仍占用 Dock 图标的问题，现在是名副其实的纯菜单栏应用
- 修复设置页版本号一直显示 `1.0.0`、“关于”弹窗版本号写死的问题，二者现在都跟随实际发布版本

## 发布资产

- `BangumiBar-1.2.0-arm64.dmg`

> 与 1.1.1 不同，本次仅提供 dmg：打包配置的 macOS 目标只有 dmg，`zip` / `tar.gz` 不在生成范围内。

## 升级说明

- 直接覆盖安装即可，登录状态与本地缓存不受影响，无需重新授权
- 首次运行会重新抓取一次放送表；若当时取不到，界面会以降级模式工作，下次刷新时自动恢复

## 已知说明

- 当前 macOS 版本仍为未签名版本
- 首次打开时，系统可能提示无法验证开发者，需要在 macOS 中手动放行
- Windows 与 Linux 打包入口仍然保留，但本次发布资产以当前机器生成的 macOS arm64 版本为主
- access token 目前仍存放在渲染层 `localStorage`。CSP 的 `connect-src 'none'` 已经堵掉用 fetch 外传的路径，彻底迁到主进程存储需要处理登录态迁移，留待后续版本
